# Інструкція: доступи Meta, щоб бот читав повний текст реклами

Дата: 2026-09-05. Для кого: власник бізнес-акаунта Meta (goverla_shop, covercar_ua) або маркетолог з правами адміністратора бізнесу.
Час: 15-20 хвилин на один магазин.

## Навіщо

Коли клієнт відповідає на рекламу в Instagram, Meta передає боту лише ID оголошення та скорочену назву («Вʼязана чоловіча кофта…»). Повний текст поста з артикулом не передається. Бот уміє дотягнути його сам через Meta Graph API, але для цього системному користувачу бізнесу потрібні три активи і чотири дозволи. Зараз їх немає, Meta відповідає «Application does not have permission».

Що зміниться після налаштування: відповідь на будь-яку нову рекламу одразу дає правильний товар за артикулом із поста, навіть якщо оголошення ще не синхронізоване в CRM і не привʼязане вручну.

## Що потрібно знати перед початком

| Магазин | Рекламний кабінет | Instagram | Business ID Instagram |
|---|---|---|---|
| goverla_shop | act_1034845985392821 | @goverla_shop | 17841403143124762 |
| covercar_ua | подивитись у CRM covercar → Рекламні витрати (колонка «кабінет») | @covercar_ua | у ключах воронки covercar, INSTAGRAM_BUSINESS_ID |

Системний користувач, з яким працюємо: той, чий токен зараз лежить у CRM як META_SYSTEM_USER_TOKEN (Налаштування → Секрети). Якщо не памʼятаєте, який саме: у Meta в списку системних користувачів зазвичай один-два, беріть того, у кого вже призначений рекламний кабінет.

## Крок 1. Відкрити системних користувачів

1. Зайти на https://business.facebook.com/settings (Налаштування бізнесу).
2. Ліворуч: Користувачі → Системні користувачі (System users).
3. Обрати потрібного користувача. Якщо його немає, натиснути «Додати», тип «Адміністратор», назва наприклад `fineko-bot`.

## Крок 2. Призначити активи

У картці системного користувача натиснути «Призначити активи» (Assign assets). Потрібно зробити три призначення, кожне окремо:

1. Тип активу «Рекламні кабінети» → обрати кабінет магазину → увімкнути «Перегляд ефективності» (View performance). Повний доступ не потрібен.
2. Тип активу «Сторінки» → обрати сторінку Facebook, до якої привʼязаний Instagram магазину → увімкнути «Контент» (Content). Якщо сторінки в списку нема, спершу перевірте в Налаштування бізнесу → Акаунти → Сторінки, що вона додана до бізнесу.
3. Тип активу «Акаунти Instagram» → обрати @goverla_shop (або @covercar_ua) → увімкнути «Контент» (Content).

Зберегти. Саме пункт 3 зараз відсутній, через це Meta не віддає підпис поста.

## Крок 3. Згенерувати новий токен

1. У тій же картці натиснути «Згенерувати новий токен» (Generate new token).
2. Додаток: обрати той, через який працює синхронізація витрат у CRM (зазвичай у списку один).
3. Термін дії токена: «Ніколи» (Never expire).
4. Позначити дозволи:
   - ads_read
   - pages_read_engagement
   - pages_show_list
   - instagram_basic
   - business_management (якщо вже стоїть, лишити)
5. Натиснути «Згенерувати», скопіювати токен і одразу зберегти його в надійному місці. Повторно Meta його не покаже.

Старий токен продовжить працювати, синхронізація витрат не зупиниться.

## Крок 4. Перевірити дозволи додатка

1. Зайти на https://developers.facebook.com/apps → обрати той самий додаток.
2. Ліворуч «Use cases» (Варіанти використання) або «App Review → Permissions and Features».
3. Переконатися, що додані: instagram_basic, pages_read_engagement, pages_show_list, ads_read. Якщо чогось нема, додати кнопкою «Add» або через відповідний use case.
4. App Review проходити не потрібно: усі активи належать тому ж бізнесу, що й додаток, для власних акаунтів дозволи діють одразу.

## Крок 5. Покласти токен у CRM

1. Зайти в CRM → магазин goverla_shop → Автоматизації → блок «Instagram / Meta Ads» → «Meta System User Token». Вставити новий токен, зберегти.
2. Повторити для магазину covercar_ua (якщо обидва магазини в одному бізнесі й системний користувач має обидва набори активів, токен один і той самий).
3. Після збереження CRM сама передає ключ у воронки магазину. Щоб переконатись, натиснути на тій же сторінці «Передати ключі у воронку»: у звіті має бути «оновлено: META_SYSTEM_USER_TOKEN» або «усе вже актуальне».

У воронці нічого вручну не міняти. Ключ INSTAGRAM_ACCESS_TOKEN теж не чіпати: бот спершу пробує його, потім системний токен.

## Крок 6. Перевірити результат

1. З будь-якого тестового акаунта Instagram відкрити рекламу магазину і натиснути «Надіслати повідомлення», написати «Яка ціна?».
2. У flows.fineko.space → Сесії → знайти цю сесію → вкладка з контекстом.
3. Має бути поле adCaption з повним текстом поста (з артикулом) і НЕ має бути поля adCaptionError.
4. Бот у відповідь має одразу показати картку саме цього товару.

Якщо adCaptionError лишився, його текст прямо називає, чого бракує:
- «Application does not have permission» → не призначено Instagram-акаунт (крок 2.3) або нема instagram_basic (крок 3-4).
- «does not exist, cannot be loaded due to missing permissions» на ID оголошення → не призначено рекламний кабінет (крок 2.1) або нема ads_read.
- «Cannot parse access token» → токен вставлено з пробілом чи обрізано, вставити заново.

## Що бот робить, поки доступів немає

Порядок спрацювання без повного тексту: ручна привʼязка оголошення в CRM → привʼязка сусідніх оголошень з тією ж назвою → артикул із повідомлення клієнта чи пересланого поста → збіг слів назви реклами з назвами товарів → розпізнавання картинки реклами → список товарів категорії з цінами. Тобто клієнт без відповіді не лишиться, але для нового оголошення з двома схожими товарами (дві «вʼязані кофти») бот може попросити артикул замість того, щоб показати товар одразу.
